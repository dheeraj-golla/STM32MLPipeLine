# Accelerometer Pipeline on B-L4S5I-IOT01A

**Goal:** Read raw XYZ data from the LSM6DSL accelerometer over I2C, compute L2 norm,
print values over UART to your PC, and blink LED2 when the norm exceeds a threshold.

This directly mirrors the ZDLB pipeline:
`Fill50msBuffers → PrePredictGate → detection flag`
...but without the XGBoost inference in the middle.

**Why this matters:** This is the data path your ML models will consume.
Understanding it here means you understand where your feature vectors come from on-device.

---

## Hardware context

The LSM6DSL (3D accelerometer + gyroscope) on the B-L4S5I-IOT01A is connected to the
STM32L4S5 via **I2C2** (pins PB10/PB11). This is already configured by CubeMX when you
selected the board with "Initialize all peripherals."

The LSM6DSL I2C address is **0xD4** (write) / **0xD5** (read) — i.e. 7-bit address 0x6A
with SA0 pin high, left-shifted by 1 for HAL.

UART output goes over **USART1**, which is connected to the ST-LINK Virtual COM Port (VCP).
This means you can read printf output from your PC over the same USB cable used for flashing.

---

## Step 1 — Verify I2C2 and USART1 are enabled in CubeMX

Open `blink_led.ioc` in CubeMX (double-click it in CubeIDE Project Explorer).

Check **Pinout & Configuration → Connectivity**:
- **I2C2** should be present and set to I2C mode
- **USART1** should be present and set to Asynchronous mode

If either is missing, enable it and regenerate code. Since you selected the board with
full peripheral init, both should already be there.

---

## Step 2 — Redirect printf to UART

By default, `printf` on bare metal goes nowhere. You need to redirect it to USART1.

In `Core/Src/main.c`, add this inside `/* USER CODE BEGIN Includes */`:

```c
/* USER CODE BEGIN Includes */
#include <stdio.h>
/* USER CODE END Includes */
```

Then add this function inside `/* USER CODE BEGIN 0 */` (before `main()`):

```c
/* USER CODE BEGIN 0 */
int __io_putchar(int ch)
{
    HAL_UART_Transmit(&huart1, (uint8_t *)&ch, 1, HAL_MAX_DELAY);
    return ch;
}
/* USER CODE END 0 */
```

This hooks `printf` into HAL's UART transmit. `huart1` is the handle generated by CubeMX
for USART1.

---

## Step 3 — LSM6DSL register definitions

Add these defines inside `/* USER CODE BEGIN PD */` (Private defines section):

```c
/* USER CODE BEGIN PD */
#define LSM6DSL_ADDR            (0x6A << 1)   // 7-bit addr 0x6A, shifted for HAL
#define LSM6DSL_WHO_AM_I        0x0F
#define LSM6DSL_CTRL1_XL        0x10          // Accelerometer control register
#define LSM6DSL_OUTX_L_XL       0x28          // First output register (X low byte)
/* USER CODE END PD */
```

---

## Step 4 — Write helper functions

Add these inside `/* USER CODE BEGIN 0 */` (alongside `__io_putchar`):

```c
/* LSM6DSL register write */
void LSM6DSL_WriteReg(uint8_t reg, uint8_t value)
{
    uint8_t buf[2] = {reg, value};
    HAL_I2C_Master_Transmit(&hi2c2, LSM6DSL_ADDR, buf, 2, HAL_MAX_DELAY);
}

/* LSM6DSL register read */
uint8_t LSM6DSL_ReadReg(uint8_t reg)
{
    uint8_t val = 0;
    HAL_I2C_Master_Transmit(&hi2c2, LSM6DSL_ADDR, &reg, 1, HAL_MAX_DELAY);
    HAL_I2C_Master_Receive(&hi2c2, LSM6DSL_ADDR, &val, 1, HAL_MAX_DELAY);
    return val;
}

/* Read 6 bytes of accel data (X, Y, Z each 2 bytes little-endian) */
void LSM6DSL_ReadAccel(int16_t *x, int16_t *y, int16_t *z)
{
    uint8_t reg = LSM6DSL_OUTX_L_XL;
    uint8_t buf[6];
    HAL_I2C_Master_Transmit(&hi2c2, LSM6DSL_ADDR, &reg, 1, HAL_MAX_DELAY);
    HAL_I2C_Master_Receive(&hi2c2, LSM6DSL_ADDR, buf, 6, HAL_MAX_DELAY);
    *x = (int16_t)(buf[1] << 8 | buf[0]);
    *y = (int16_t)(buf[3] << 8 | buf[2]);
    *z = (int16_t)(buf[5] << 8 | buf[4]);
}
```

## Step 5 — Initialize the LSM6DSL and read data in main()

Inside `/* USER CODE BEGIN 2 */` (after peripheral init, before the while loop):

```c
/* USER CODE BEGIN 2 */

// Verify sensor is alive
uint8_t who_am_i = LSM6DSL_ReadReg(LSM6DSL_WHO_AM_I);
printf("LSM6DSL WHO_AM_I: 0x%02X (expect 0x6A)\r\n", who_am_i);

// Configure accelerometer: 104 Hz ODR, +/-2g full scale
// CTRL1_XL: ODR=0100 (104Hz), FS=00 (2g), LPF2=0, BW=00
LSM6DSL_WriteReg(LSM6DSL_CTRL1_XL, 0x40);

/* USER CODE END 2 */
```

Then inside the `while(1)` loop, replace (or extend) the blink code:

```c
/* USER CODE BEGIN WHILE */
while (1)
{
    int16_t ax, ay, az;
    LSM6DSL_ReadAccel(&ax, &ay, &az);

    // Convert raw counts to float (sensitivity = 0.061 mg/LSB at +/-2g)
    float ax_f = ax * 0.061f;
    float ay_f = ay * 0.061f;
    float az_f = az * 0.061f;

    // Compute L2 norm (same as vibe_mean_l2_norm in ZDLB)
    float norm = sqrtf(ax_f*ax_f + ay_f*ay_f + az_f*az_f);

    printf("X: %7.2f  Y: %7.2f  Z: %7.2f  |norm|: %7.2f mg\r\n",
           ax_f, ay_f, az_f, norm);

    // Detection gate: blink LED if norm exceeds threshold
    // At rest, norm should be ~1000 mg (gravity). Tap will spike it.
    if (norm > 1200.0f) {
        HAL_GPIO_WritePin(LED2_GPIO_Port, LED2_Pin, GPIO_PIN_SET);
    } else {
        HAL_GPIO_WritePin(LED2_GPIO_Port, LED2_Pin, GPIO_PIN_RESET);
    }

    HAL_Delay(100);   // 10 Hz sample rate for now

    /* USER CODE END WHILE */
}
```

Add `#include <math.h>` to the includes section (alongside `<stdio.h>`).

---

## Step 6 — Add math library to linker

The `sqrtf` function requires linking the math library. In CubeIDE:

**Project → Properties → C/C++ Build → Settings → MCU GCC Linker → Libraries**

Add `m` to the libraries list (just the letter m, no `-l` prefix — CubeIDE adds that).

---

## Step 7 — Build and flash

Build with **Ctrl+B**, then **Run → Run As → STM32 C/C++ Application**.

---

## Step 8 — View UART output on your PC

The UART output comes through the ST-LINK USB cable as a Virtual COM Port.

On Windows:
1. Open **Device Manager** → Ports (COM & LPT) → note the COM port number for "STMicroelectronics STLink Virtual COM Port"
2. Open a serial terminal — simplest option is the one built into CubeIDE:
   **Window → Show View → Other → Terminal → Terminal**
   Or use PuTTY / TeraTerm.
3. Connect at **115200 baud, 8N1**

You should see the XYZ values and norm printing at 10 Hz. Tap the board and watch the norm spike.

## What you've built

```
LSM6DSL (I2C2) → raw int16 XYZ counts
    → scale to mg (float32)
    → L2 norm (float32)
    → threshold gate → LED2
    → UART/printf → PC terminal (verifiability)
```

This is a minimal but complete sensor → feature → decision pipeline in C.
The next step is replacing the threshold gate with XGBoost inference.

---

## Notes for Gridware context

- On real Gridscopes, raw sensor reads happen in a dedicated HAL service, not in `main()`
- Data flows through CircularBuffers and is consumed by the DSP engine before reaching the ML layer
- The `DspProcessedBlob_t` that ZDLB receives is equivalent to the `norm` computed here,
  but with more sophisticated DSP (envelopes, decimation, filtering) applied upstream
- The UART printf here is your "verifiability" mechanism — equivalent to what you'd need
  to instrument on a real Gridscope to verify intermediate ML calculations
